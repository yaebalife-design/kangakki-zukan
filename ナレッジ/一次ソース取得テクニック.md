# 一次ソース取得テクニック（コスメの代わり手帖）

最終更新: 2026-09-03

記事材料を一次ソースだけで集めるときに、実際に効いた手法だけを記録する。
「取れなかった」と報告する前に、必ずこのファイルの手順を全部試すこと。

---

## 1. 🔴 403 / 404 はヘッダー不足が原因のことが多い

資生堂系ブランドサイト（`maquillage.shiseido.co.jp`）とSUQQU（`www.suqqu.com`）は、
User-Agentだけでは403や404を返すが、**ブラウザ相当のヘッダーを揃えると200が返る**。

```powershell
$UA = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36"
$H = @{
  "Accept"                    = "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8"
  "Accept-Language"           = "ja,en-US;q=0.9"
  "Upgrade-Insecure-Requests" = "1"
  "Sec-Fetch-Dest"            = "document"
  "Sec-Fetch-Mode"            = "navigate"
  "Sec-Fetch-Site"            = "none"
  "Sec-Fetch-User"            = "?1"
}
$r = Invoke-WebRequest -Uri $u -TimeoutSec 40 -UserAgent $UA -Headers $H -UseBasicParsing
```

WebFetchツールが404を返しても、この方法なら200になることがある。**WebFetchの結果だけで「ページが存在しない」と判定しない。**

## 2. 🔴 日本語が化けるときは RawContentStream から読む

`$r.Content` は文字化けする。必ずこちら。

```powershell
$body = [System.Text.Encoding]::UTF8.GetString($r.RawContentStream.ToArray())
$t = [regex]::Replace($body, '<(script|style)[\s\S]*?</\1>', ' ')
$t = [regex]::Replace($t, '<[^>]+>', ' ')
$t = ([System.Net.WebUtility]::HtmlDecode($t)) -replace '\s+', ' '
```

## 3. 🔴 Wayback Machine は初回失敗が普通。指数バックオフで4〜5回リトライする

503やタイムアウトが返っても**必ず再試行する**。「アーカイブにアクセスできない」と報告してはいけない。

- CDX一覧: `https://web.archive.org/cdx/search/cdx?url=<encoded>&output=json&filter=statuscode:200&collapse=timestamp:6&limit=-12`
  - `&from=20260101` で期間を絞れる
  - URLに `*` を付けるとサブパス全体を列挙できる（例: `maquillage.shiseido.co.jp/item/base/*`）
- 再生: `https://web.archive.org/web/<timestamp>/<url>`

**アーカイブがサーバーサイドレンダリング済みのことがある。** SUQQUは現在JSで描画されるが、
Waybackのスナップショットは本文・価格・内容量・商品詳細まで完全に含まれていた。

## 4. 🔴 告知を出さないブランドは「カテゴリ一覧アーカイブの差分」で挟み込む

販売終了告知を出さないブランド（SUQQU・NARS・シュウ ウエムラ・セルヴォーク・ヴィセ）でも、
**公式カテゴリ一覧の複数時点のアーカイブ**を取り、対象商品名の有無を調べれば
「最後に掲載を確認できた時点」と「最初に不在を確認できた時点」で掲載終了時期を挟み込める。

これは**終了日を推測せずに書ける事実**なので、当サイトの「嘘ゼロ」ルールと相性がよい。
実績: SUQQU リタッチ プレスト パウダー（2025.1.13〜4.24）、トーン タッチ アイズ（2025.5.12〜8.6）、
シアー マット リップスティック（2025.11.18〜2026.3.12）。

記事には「販売終了日は未確認。公式一覧から消えたのは○〜○の間」と書く。日付を断定しない。

## 5. JS描画で商品が取れないサイトは、ページが読んでいるJSONを探す

マキアージュの商品一覧はVue+axiosで、`/assets/js/list.js` の中に
`/assets/js/products/products.json` というエンドポイントがあった。全41商品のJSONが素で取れる。

手順: HTMLから `<script src=...>` を拾う → そのJSを取得 → `.json` / `.php` を含む文字列を探す。

## 6. 商品ページのHTMLに埋め込まれたJSONに公式色名が入っていることがある

SUQQUの一部商品ページは、HTML内に `colorCode\":\"MS-04 麗朱 - URUWAAKA\"` の形で全色名を持つ。

```powershell
[regex]::Matches($raw, 'colorCode\\":\\"([^\\]+)') | ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
```

ただし全商品にあるわけではない。無ければ素直に「色数：確認中」と書く。

## 7. 資生堂の一次ソースは3系統ある。使い分ける

| ソース | 取れるもの | 注意 |
|---|---|---|
| 生産終了品DB `shiseido.co.jp/scp/products/end/index.php` | 終了年月・内容量・JAN13・発売日・色番＋公式色名 | POST・ブランドコード指定。🔴 **生産終了から2年で掲載終了**するので取得都度スナップショット保存 |
| ブランドサイト `brand.shiseido.co.jp` 等 | 税込価格・色数・キャッチコピー・発売日 | ヘッダー必須（§1） |
| 資生堂オンラインストア `shiseido.co.jp/sw/onlinestore/` | 内容量・商品サイズ・タイプ・原産地・販売名・成分 | 🔴 **価格だけJS描画で取れない**。価格はブランドサイト側から取る |

## 8. 🔴 資生堂FAQは必ず引く。ただし件数ではなく中身を見る

DBは後継を名指ししない方針だが、**FAQには個別に後継を名指しするQ&Aが実在する**
（例: リバイタル グラナス イリデッセント ベース → インウイ グロー プライマー）。

`https://faq.wp.shiseido.co.jp/category/search/8?keyword=<encoded>&site_domain=support`

⚠️ **ヒット件数で判断してはいけない。** 形態素解析で部分一致が大量に混ざる。
実例: 「ドラマティックフォルミンググロウベース」で11件ヒットしたが、
全件が別商品のQ&Aだった。必ず `生産終了品「...」` の対象商品名を全件抜き出して照合する。

```powershell
[regex]::Matches($t, '生産終了品「[^」]{2,40}」') | ForEach-Object { $_.Value } | Sort-Object -Unique
```

## 9. 🔴 在庫判定は「品切れ」だけ見てはいけない（2026-09-05に実害が出た）

資生堂の商品ページは在庫状態が**3種類**ある。

| 表示 | 意味 | 判定に使う文字列 |
|---|---|---|
| カートに入れる | 購入可 | `カートに入れる` |
| **入荷待ち** | 買えない（再入荷待ち） | `再入荷通知を希望する` / `入荷待ち 店舗検索` |
| 品切れ | 買えない | `品切れ 店舗検索` |

🔴 **`if "品切れ" in text` だけで判定すると「入荷待ち」を「購入可」と誤判定する。**
これで6記事の在庫記述が事実と逆になり、レビューで発見された。正しい判定：

```python
def stock_state(t):
    if "再入荷通知を希望する" in t or "入荷待ち 店舗検索" in t:
        return "入荷待ち"
    if "品切れ 店舗検索" in t:
        return "品切れ"
    if "カートに入れる" in t:
        return "購入可"
    return "不明"
```

さらに注意：
- **色展開のある商品は「色ごとの在庫」と「商品としての購入可否」が別**。
  色欄に `品切れ - Silk/310` があっても、他の色が買えれば商品としては購入可。
  記事には**色単位で書く**（「6色中1色が品切れ」）。商品単位の書き方だと読者が誤解する
- **在庫表示は日々変わる**。記事には必ず確認日を併記し、「公式ページで最新の表示をご確認ください」を添える

## 10. 🔴 サイズ違いは別JAN。価格は「どのサイズの価格か」を必ず確認する

同一商品で30mL/50mLがある場合、**URLのJANごとに価格が違う**。
ページ内の埋め込みJSONの `"variant"` を見れば、そのURLがどのサイズかが分かる。

```python
re.findall(r'"variant"\s*:\s*"([^"]+)"', raw_html)   # 例 ['50mL']
```

実害の例（2026-09-05に修正）:
- ベネフィアンス ブライトニング マイクロS セラム … 記事が書いた19,250円は**50mL**の価格。
  30mLは別JAN `4514254204870` で**14,850円**。差額の記述が5,500円→1,100円に訂正
- アルティミューン パワライジング セラム … 15,180円は**50mL**。30mLは`4514254207604`で**9,900円**。
  「15,180円から」は最安と逆だった

→ **「◯◯円から」と書くときは、必ず全サイズのJANを引いて最安を確かめる。**

## 11. リダイレクト先で「実質の後継案内」を検出する

旧商品URLが**別商品の詳細ページへ301**する場合、公式が実質的に後継を案内しているとみなし、
ローカルルール8により**採用不可**とする（例: CPB オンブルプードルソロ → オンブルクルールソロ）。

リダイレクト先がトップページ・カテゴリページ・エラーページなら採用可。
`410 Gone` は完全撤去で、後継誘導なしなので採用可。
